MDB React Native Manual

react-native-mdb puts the complete CM30 MDB Cashless Device stack behind a JavaScript API: the proven hardware-lib and mqtt-lib Kotlin libraries ship inside the package, and every native function and callback is mirrored 1:1 as a JS function or event. Android-only — the CM30 hardware runtime is armeabi-v7a.

01 · SetupInstall

npm install <path-to>/react-native-mdb    # or publish to your own registry

Autolinking registers the native module — no settings.gradle or MainApplication edits. Two requirements in your app's android/build.gradle:

  • minSdkVersion = 30 — the CM30 terminal runs Android 11 and the AARs are built for it.
  • Nothing else. The three AARs (hardware-lib-7.9.2, mqtt-lib-2.0.0, CM30-HardwareLibrary-1.0.9) are bundled inside the package's android/libs.

Local development note. If you install the library from a local folder that sits outside your app directory (a file: dependency), Metro needs to be told where it lives — see the demo's metro.config.js (watchFolders + resolver.nodeModulesPaths). A normal registry install needs none of this.

02 · BootQuick start

import Mdb from 'react-native-mdb';

const deviceId = await Mdb.getSuggestedDeviceId(); // last 6 of ANDROID_ID, uppercased
Mdb.initMqtt('cm30-mdb/hamdan-rabbah', deviceId,     // OPTIONAL - see below
            { host: 'uat-api.rabbah.sa', username: 'rabbah', password: '...' });
Mdb.startMqtt();
Mdb.initMdb();
Mdb.startMdb();

Order matters only in one place: call initMqtt before initMdb if you want the dashboard link, so the MDB engine can register its command listener on the live connection.

MQTT is optional. Skip initMqtt/startMqtt entirely and the MDB engine runs fully offline — vending, events, settings and configs all work. Log lines simply stay on-device. Nothing throws.

03 · MoneyThe payment flow

Four events cover the whole life of a transaction:

Mdb.setCancelMode('vendDenied');   // once ever - persisted across restarts

const subs = [
  Mdb.onVendRequest(async ({ amount, minorUnits, itemNumber }) => {
    // minorUnits = 350  -> EXACT integer halalas. Send THIS to the gateway.
    // amount     = 3.5  -> decimal, display only: amount.toFixed(2)
    const ok = await gateway.authorize(minorUnits);
    if (ok) await Mdb.approveVend();
    else    await Mdb.cancelVend();          // sends the standing cancel mode
  }),
  Mdb.onVendSuccess(({ itemNumber }) => gateway.capture()),  // product dispensed
  Mdb.onVendFailure(() => gateway.refund()),                 // jam - customer got nothing
  Mdb.onSessionEnded(() => clearTransactionState()),         // fires after EVERY outcome
];
// on unmount: subs.forEach(s => s.remove());
  • onVendRequest — the customer picked an item. The machine is now waiting for your answer; authorize the payment and reply with approveVend() or cancelVend(). Scale factor and decimal places from READER_CONFIG_DATA are already applied — no math on your side.
  • onVendSuccess — the machine confirmed the product physically dispensed. This is the capture point.
  • onVendFailure — the machine reported the vend failed after approval (jam, empty column). The customer got nothing: refund or void.
  • onSessionEnded — the session closed, on every path (success, failure, cancel, timeout). Per-transaction cleanup goes here.

cancelVend() uses the standing mode set once via setCancelMode('sessionCancel' | 'vendDenied'). For a one-off override, use cancelVendWith(mode) without touching the standing setting.

04 · APIFunctions

Everything mirrors the Kotlin API — and every remote dashboard command has a function twin here, so a fully manual app (no dashboard at all) can do everything.

MQTT optional

FunctionWhat it does
initMqtt(prefix, deviceId, options?)Configure the broker link. Topics become <prefix>/<deviceId>/liveLog and .../commands. Optional options = { host, port, username, password } for a private authenticated broker (default host mosquitto:1883, no auth).
startMqtt() / stopMqtt()Open / close the connection (auto-reconnects while started).
mqttEnqueue(line)Push your own log line onto the shared outbound queue. No-op if MQTT was never initialized.
isMqttConnected()Resolves true while the socket is live.

MDB lifecycle

FunctionWhat it does
initMdb()One-time engine init (idempotent). Wires events, restores persisted settings, publishes the settings snapshot if MQTT is up.
startMdb() / stopMdb()Start / stop the poll worker that talks to the vending machine.

Vend actions

FunctionWhat it does
beginSession()Open a session manually (only meaningful when auto-session is off and state is ENABLED).
approveVend()Answer a pending VEND REQUEST with VEND APPROVED. Resolves false if nothing is pending.
cancelVend()Deny using the standing cancel mode (set once via setCancelMode).
cancelVendWith(mode)One-time explicit deny: 'sessionCancel' or 'vendDenied'.

State

FunctionWhat it does
getCurrentState()Resolves 'INACTIVE_STATE' | 'DISABLED_STATE' | 'ENABLED_STATE' | 'VEND_STATE'.
isSessionActive()Resolves true while a session is open.

Settings persisted

Each setter also syncs the dashboard instantly (settings snapshot over MQTT) — both sides always agree.

FunctionWhat it does
setCancelMode(mode)Standing deny mode for cancelVend(): 'sessionCancel' | 'vendDenied'.
setAutoSession(bool) / isAutoSession()Auto-open a session whenever the machine enables the reader. Switching modes mid-session cancels/re-arms cleanly.
setMdbLevel(1|2|3)Which MDB level handshake the device speaks. Level 3 Always Idle comes from bit 5 of the last byte of READER_CONFIG_INFO_L3 — not from a setting.
setMqttLogging(bool)Mute / unmute the MDB log stream over MQTT. Commands, status and config sync stay alive either way.
setPollVisibility(bool)Whether per-poll lines are marked for on-screen display (they always stay off-screen-list to avoid UI freezes).
setUnhandledVisibility(bool)Same, for unhandled-command lines.
getSettingsJson()Resolves the full settings snapshot as JSON.

Price helpers

FunctionWhat it does
priceToAmount(raw)Raw 16-bit VMC price → decimal display amount (scale × decimal places applied).
priceToMinorUnits(raw)Raw price → exact integer minor units. Pure integer math — use for payments.

You rarely need these directly: onVendRequest already delivers both forms.

Helpers

NEW · hardware-lib 7.9.2Pulse output

Pulse driving over the CM30 digital IO, from JavaScript. Polarity comes from the backend boolean; the train runs through the vendor's native pulser (direction = PULSE_DIR_POSITIVE for high pulses, PULSE_DIR_NEGATIVE for low), so the width can never stretch.

await Mdb.initPulse(true);                  // true = HIGH pulses (idle LOW), false = LOW pulses (idle HIGH)
const ok = await Mdb.sendPulse(50, 100, 3); // width ms, period ms, count - resolves ~period x count later
                                            // true only when EVERY pulse physically went out
await Mdb.getPulseState();                  // { initialized, highPulse, pendingTrains }
await Mdb.setReadyFeedback(model.supportReadyFeedback, model.readyFeedbackValue); // dashboard flag
await Mdb.isMachineReady();                 // digital-in check now - sendPulse runs it automatically

sendPulse resolves only after the train finishes; other Mdb calls keep working meanwhile (the wait happens off RN's native-modules thread). Call initPulse before the first train - it drives the idle level immediately and can be re-called whenever the backend changes the setting. vendorPulse(p1,p2,p3,p4) is a raw passthrough for experiments. Dashboard equivalents: initPulse:true|false, sendPulse:50,100,3.

05 · APIEvents

Each subscription returns an object with .remove() — always unsubscribe on unmount.

EventPayloadWhen
onVendRequest{ amount, minorUnits, itemNumber }Customer picked an item; the machine is waiting for approve/deny.
onVendSuccess{ itemNumber }Product physically dispensed — capture the payment.
onVendFailure—Vend failed after approval — refund.
onSessionEnded—Session closed, on every outcome — cleanup.
onLog{ line, showOnScreen }Every engine log line. Never render showOnScreen: false lines into a growing list.
onStatus{ json }VMC status — instantly on every state change, plus a recentActivity flip (event-driven, no periodic heartbeat).
onRemoteCommand{ command }A dashboard command the MDB engine did not recognize — your app's own custom commands arrive here.
MdbStateChanged{ state }New in hardware-lib 7.9.2 (raw DeviceEventEmitter name). Edge-triggered on every transition: INACTIVE_STATE / DISABLED_STATE / ENABLED_STATE / VEND_STATE — never fires on heartbeats.
MdbExchange{ code, name, rxHex, txName, message, sessionId? }New in hardware-lib 7.9.2 (raw DeviceEventEmitter name). One per bus exchange, with its stable integer CMD code (111 = RESET→ACK, 112 = POLL→JUST RESET, 113 = SETUP→READER CONFIG, 114 = EXPANSION→PERIPHERAL ID, ... full table in the Library Manual).

Since hardware-lib 7.9.2 the Kotlin engine ships no networking; the MQTT glue lives inside the native module's initMdb(), so JS usage is completely unchanged.

06 · PayloadsHex configs

Every reply payload the device sends on the bus is editable at runtime — from JS here, or from the dashboard; both paths write the same store and every change re-syncs the dashboard's Config panel. 

import Mdb, { ConfigName } from 'react-native-mdb';

const hex  = await Mdb.getConfigHex(ConfigName.READER_CONFIG_INFO_L3);
const err  = await Mdb.setConfigHex(ConfigName.SESSION_BEGIN, '03 FF FF');
if (err) console.warn('rejected:', err);   // resolves null on success, else the reason
await Mdb.resetConfig(ConfigName.SESSION_BEGIN);          // back to the built-in default
const names = await Mdb.configNames();                    // all editable payload names
const snap  = await Mdb.configSnapshotJson();             // full JSON snapshot

Lengths are locked to the protocol — a wrong-length hex string is rejected with a clear message, never silently truncated — with one exception: the two BEGIN SESSION payloads accept any length from 1 to 35 bytes, because some feature-level-2 machines only accept the short Level-1-style 3-byte form (03 FF FF). Available names on ConfigName: JUST_RESET, CAN, READER_CONFIG_DATA, READER_CONFIG_INFO, READER_CONFIG_INFO_L3, VEND_APPROVED, VEND_DENIED, END_SESSION, SESSION_CANCEL, SESSION_BEGIN, SESSION_BEGIN_L2, REVALUE_LIMIT, REVALUE_DENIED (the reply to a REVALUE REQUEST — default 0E, denied).

07 · OpsDashboard

The same dashboard/log-viewer.html used with the native app works unchanged — the wire protocol is identical. Open it in any browser, pick the device from the dropdown, and every remote command (level select, session mode, cancel mode, config edits, MQTT log mute, ping) runs in parallel with your JS calls: both paths execute the same Kotlin code and stay in sync.

08 · ReferenceDemo app & building

MdbDemo/App.tsx is the reference integration: live state badge, capped inverted log list, and a vend approval sheet showing both amount and minorUnits.
